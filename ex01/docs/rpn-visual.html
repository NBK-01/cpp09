Postfix, One Stack evaluate reverse-Polish notation with nothing but push and pop

Reverse Polish Notation writes the operator after its operands: 3 4 + instead of 3 + 4. That tiny reordering kills the need for parentheses and precedence rules entirely — a single stack and one left-to-right pass is all it takes to evaluate any expression.

input
"3 4 + 5 *"
output
35

Reads as (3 + 4) × 5. The parentheses are implied by the position — never written.

idea

Why postfix needs no parentheses

In normal (infix) math, 3 + 4 × 5 is ambiguous until you know that × binds tighter than +. Postfix removes the ambiguity by baking the order into the sequence itself — the moment you see an operator, its two operands are already sitting right in front of you.

infix — what humans write
(3 + 4) × 5

Needs parentheses and precedence rules to know + happens first.

postfix — what RPN writes
3 4 + 5 ×

Unambiguous. Scan left to right; an operator always acts on the two most-recent values.

01

The one rule, applied token by token

Walk the tokens left to right. Two cases only: a number gets pushed onto the stack; an operator pops the top two, combines them, and pushes the single result back. Here is "3 4 + 5 *" traced in full — the stack shown bottom → top after each step.

The final check. A well-formed expression leaves exactly one value on the stack. Anything else — zero, or more than one leftover — means the input was malformed.

02

The subtlety: which operand is which

For + and × order doesn't matter, but for - and / it absolutely does. The stack pops in reverse of how things went in: the first pop is the right operand (b), the second pop is the left (a). So "7 3 -" must compute a − b = 7 − 3, not 3 − 7.

correct
b = pop() → 3
a = pop() → 7
a − b = 7 − 3 = 4 ✓
the trap
If you did top − second instead you'd get
3 − 7 = −4 ✗
Same for division.

In the code: b = _stack.top(); _stack.pop(); a = _stack.top(); _stack.pop(); then apply(a, b, op).

03

What counts as valid — and every way it can fail

The subject restricts operands to single digits (0–9) and operators to + − × ÷. So each token must be exactly one character. Anything outside that, or a stack that doesn't balance, throws immediately with a clear message.

Token longer than 1 char

Multi-digit or garbage tokens are rejected up front.

"42 5 +" → bad expression

Operator, too few operands

An operator needs 2 values waiting. Fewer than 2 on the stack → error.

"3 +" → bad expression

Leftover operands

Ends with more than one value on the stack — operators are missing.

"3 4 5 +" → bad expression

Unknown character

Anything that isn't a digit or a known operator.

"3 4 %" → bad expression

Division by zero

Caught inside apply() before the divide happens.

"5 0 /" → division by zero
code

The entire evaluator in one loop

The class wraps a single std::stack<double>. Tokenizing is handed to an istringstream (it splits on whitespace for free), so evaluate() is just the rule above written out.

01 Tokenize & branch — RPN::evaluate
std::istringstream iss(expr);
str tok;
while (iss >> tok) {                 // split on whitespace
  if (tok.size() != 1)
    throw std::runtime_error(ERR_BAD); // single char only
  char c = tok[0];
  if (std::isdigit(c))
    _stack.push(c - '0');          // number → push
02 Operator — pop two in the right order, push one
  else if (c=='+'||c=='-'||c=='*'||c=='/') {
    if (_stack.size() < 2)
      throw std::runtime_error(ERR_BAD);
    double b = _stack.top(); _stack.pop(); // right operand
    double a = _stack.top(); _stack.pop(); // left operand
    _stack.push(apply(a, b, c));
  } else
    throw std::runtime_error(ERR_BAD);   // unknown token
}
03 Final check & the math — apply
if (_stack.size() != 1)           // must balance to one
  throw std::runtime_error(ERR_BAD);
return _stack.top();

// apply(a, b, op):
case '/':
  if (b == 0) throw std::runtime_error(ERR_DIV);
  return a / b;                    // a is left, b is right
O(n)

One pass, one stack. Each token is touched exactly once and does constant work — the whole evaluation is linear in the number of tokens, with no backtracking and no parse tree.
